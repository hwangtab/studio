# Image Optimization Workflow

이 문서는 정적 이미지 자산을 최적화하는 절차와 검증 방법을 정리한 것입니다.

## 자동화 스크립트

- 실행 명령: `npm run optimize-images`
- 스크립트 동작
  - `public/images/` 아래의 JPG, JPEG, PNG 파일을 모두 탐색합니다.
  - 각 이미지를 최대 폭 `480 / 960 / 1440px`(원본보다 큰 경우 원본 크기로 자동 조정)으로 리사이즈합니다.
  - 동일한 폭에 대해 WebP 버전과 원본 포맷(또는 JPG) 버전을 `public/images/optimized/`에 생성합니다.
  - 원본보다 최신 타임스탬프를 가진 결과물이 있다면 재생성하지 않고 건너뜁니다.
- 빌드 전 단계인 `npm run build`에서도 자동 실행되도록 `prebuild` 스크립트에 포함되어 있습니다.

## 수동 확인 체크리스트

1. **변환 결과물**  
   - `public/images/optimized/` 폴더에 `*-480w.*`, `*-960w.*`, `*-1440w.*` 파일이 생성되었는지 확인합니다.
   - 새 이미지를 추가했다면 스크립트 실행 후 결과물이 생겼는지 반드시 확인합니다.

2. **로컬 빌드**  
   - `npm start`로 개발 서버를 실행하여 주요 페이지(Home, About, Studio, PracticeRoom, Portfolio)를 확인합니다.
   - 브라우저 DevTools(Network 탭)에서 이미지가 `optimized/` 경로로 로드되는지, WebP가 우선 선택되는지 확인합니다.

3. **배포용 빌드**  
   - `npm run build` 실행 시 오류가 없는지 확인하고, `build/` 폴더 안에 참조된 이미지 경로가 올바른지 확인합니다.

4. **성능 측정(선택)**  
   - Lighthouse 또는 WebPageTest로 LCP, CLS 등 지표를 측정하여 최적화 전후 결과를 비교합니다.
   - 특히 모바일 뷰포인트에서 이미지가 빠르게 로드되는지 집중적으로 확인합니다.

## 유지보수 팁

- 새 이미지를 추가하거나 교체한 뒤에는 `npm run optimize-images`를 다시 실행하세요.
- 큰 사이즈의 PNG 파일은 가능하다면 배경 투명도가 필요할 때만 사용하고, 그 외에는 JPG로 저장하면 용량을 줄일 수 있습니다.
- 자동화 스크립트는 여러 번 실행해도 안전하며, 원본보다 최신인 결과물은 건너뛰므로 CI에서도 재사용 가능합니다.
