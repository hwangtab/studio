# 관리자 대시보드·재무 통합 검토 (2026-10-22)

운영자 요청: "매출·지출·수입을 관리하는 별도의 통합 페이지를 두고, 대시보드에는 수익만 간략히. 대시보드에서 주요한 내용을 볼 수 있게."
재무·UX/정보구조·현장 운영·엔지니어링 네 관점으로 관리자 화면을 읽기 전용으로 감사한 뒤 합의한 내용과 남은 일이다.

## 이번에 한 것 (1차)

- **재무 통합 `/admin/finance`** — 탭은 하위 경로다: 매출·수익(옛 `/admin/revenue`) / 지출(`/finance/expenses`, 옛 `/admin/expenses`) / 장부 내보내기(`/finance/export`).
  - `?tab=`이 아니라 하위 경로를 고른 이유: 매출 화면이 이미 year·month·line·type 쿼리를 쓰고, 탭마다 읽는 데이터가 크게 다르다(매출은 3년치 결제 행, 지출은 지출 표만, 내보내기는 DB를 안 읽는다).
  - 옛 주소는 `next.config.mjs` 리다이렉트(임시, 쿼리 유지) — 이미 나간 운영 점검 메일이 절대 주소로 담고 있다.
  - 메뉴: `공통`에서 매출·지출을 빼고 `재무` 묶음(매출·수익 / 지출 / 장부 내보내기 / 결제 링크). `공통`은 접속기록 + 계약 변경 이력(메뉴에 없던 화면).
- **장부 내보내기** — 대시보드 맨 아래 있던 토스 결제 장부 폼과, 매출 화면 링크로만 닿던 상점·공연 정산 CSV를 한 화면에. DB를 읽지 않아 현황이 죽어도 받을 수 있다.
- **대시보드 재구성**
  - 맨 위 요약 네 칸(긴급 · 확인 · 대기 작업 · 오늘 일정, 각 칸으로 이동).
  - 왼쪽: 처리할 일(점검 메일과 같은 판정) → 대기 작업. 약 30종의 카드 격자를 "무엇을 해야 하나" 다섯 묶음(입금 확인 / 환불·정산 송금 / 기록·발송 / 심사·확인 / 계약·구독)으로 나누고 0건은 숨겼다.
  - 오른쪽: 이번 달 수익 한 장(수익 크게, 매출·지출·전월 대비, 분야별 수익 → 재무로) → 일정(오늘 / 이번 주, 시작–끝 시각, 오늘 레슨) + 진행 중(믹싱 작업 중 등 상태) → 캘린더에만 있는 일정 → 시스템(확인 시각·소셜 토큰).
  - 수익 숫자는 재무와 같은 `buildRevenueSnapshot`. 지출 합계(`expenseTotal`)·레슨 수납 누락(`lessonMissing`)을 스냅숏에 더했다(예전엔 대시보드에서 레슨 수납 실패가 조용히 빠졌다).
- **속도** — 대시보드 gSSP가 상점 → 매출 → 현황 차례로 읽던 것을 함께 읽는다. 캘린더에만 있는 일정 읽기에 4초 상한(구글 요청 자체 상한은 8초였다).
- **작은 결함** — "매일 23시 운영 점검 메일" 문구(실제는 UTC 23시 = 한국 아침 8시), 입금 안내 기한 경과 항목의 링크가 `/admin`으로 제자리를 가리키던 것(한 종류면 그 목록, 여럿이면 `/admin#deposits`), 처리할 일 키 충돌 가능성.

## 남은 일 (우선순위 순)

1. **받을 돈·줄 돈 탭** (재무) — 데이터는 이미 있는데 화면에 금액이 없다.
   - 줄 돈: 정산 지급 예정(`funding_project_payouts`·`partner_payouts`의 net·원천징수·status), 원천징수 예수금(다음 달 10일 신고), 환불 송금 대기(`refund_accounts.refundedAt IS NULL`).
   - 받을 돈: 레슨 미수(`arrearsOf`), 월 입주 연체(`overdueDays` × 월 이용료), 계좌 입금 대기 금액.
2. **대시보드에 빠진 운영 일** (운영 점검 메일에만 있거나 아무 데도 없다)
   - 제작 계약: 진행 할 일(ledger.ts 할 일 목록 — 입금 기한·수정 반영·최종 인도·지연·무응답), 서명 대기, 서명 링크 만료 임박, 후처리 누락(high). `checkContractHygiene`는 크론에서만 돌고 앞단에 상태 변경(`expireOverdueContracts`)이 있어 판정만 떼어 내야 화면에 붙일 수 있다.
   - 제작 계약 해지 환불 송금(점검 쿼리가 `order_kind='production'`을 뺀다), 레슨 수강 계약 서명 대기, 레슨 중도 종료 환불(5일 기한).
3. **딥링크** — 공연·상점·구독·입주·레슨 목록에 상태 필터 쿼리가 없어 대기 항목을 눌러도 목록 첫 화면이 열린다. 환불 송금 이슈는 공연·상점 건도 `/admin/bookings`로 간다. href가 없는 이슈 약 12종.
4. **처리할 일 단계화** — 이슈와 대기 건수를 한 목록으로 합치고 긴급 / 오늘 / 이번 주 세 단계, 기한(경과일·D-n)과 대표 건을 보이기(`HealthIssue`에 `dueAt`·`tier`·`items` 추가).
5. **회계 정확도** — 월 입주 매출세액(이용료는 부가세 별도인데 vat 0으로 잡힌다, 운영자 확인 필요), 정산 기록에 있는 PG 수수료를 플랫폼 비용으로, 지출 항목 확장(외주·세션 실비·장비·광고·보험·세금·이자 — CHECK 확장 마이그레이션), 지출 탭 기간 선택, 월별 수익 추이, 분기 부가세 예상.
6. 메뉴에 없는 심사 화면(상점 상품 심사·공연 제출 심사), "계약" ↔ "제작 계약" 이름 비대칭.
