# naver-raw — 네이버 원시 데이터 보관

`docs/gsc-raw`·`docs/ga4-raw`와 대칭 구조다. 네이버 서치어드바이저·스마트플레이스 통계는
API로 자동 수집하는 파이프라인이 없으므로(구글 GSC/GA4와 다르게 공개 API가 제한적이다),
콘솔에서 월 1회 손으로 내려받아 여기 쌓아 둔다.

## 왜 필요한가

`docs/proposals/seo-geo-aeo-inquiry-growth-2026-09-04.md`(P0-4) 기준, 네이버 검색 리드율은
5.0%로 google organic(0.52%)의 10배인데 개선 루프에 쓰는 데이터가 0건이었다. 네이버 플레이스
경유 문의는 사이트를 거치지 않고 전화·톡톡·예약으로 바로 빠지는 경우가 많아 GA4에도 안 잡힌다
— 이 디렉토리와 `docs/oplog/quotes.csv`(채널 `naver_place`·`naver_search`)가 그 공백을 메운다.

## 무엇을 내려받는가

| 파일명 규칙 | 내려받는 화면 | 보는 것 |
|---|---|---|
| `searchadvisor-YYYY-MM.md` | 네이버 서치어드바이저 → 리포트 → 콘텐츠 노출/클릭 · 사이트 진단 · 수집 현황 | 노출·클릭·CTR, 키워드·웹문서 TOP, 색인/수집제한 |
| `smartplace-YYYY-MM.csv` | 네이버 스마트플레이스 → 통계 → 유입 / 전화 / 예약 | 플레이스 조회수·전화 연결·예약 전환 |

**서치어드바이저는 `.md`다 — 콘솔에 내보내기가 없다.** 2026-09-15 확인: 콘텐츠 노출/클릭
화면(검색 키워드·검색 웹문서 탭 모두)에 다운로드 버튼이 없고, 수집 현황·색인 현황은 canvas
차트라 숫자가 텍스트로 나오지 않는다(차트 툴팁을 하나씩 읽어야 한다). 그래서 화면 수치를
표로 옮겨 적는다. 사이트 진단 상세 화면에만 다운로드 링크가 있는데 그건 URL 목록이라
추세 비교에는 쓰지 않는다. 스마트플레이스는 CSV 내보내기가 있어 그대로 둔다.

옮겨 적을 때는 **회차 간 비교가 되도록 같은 항목·같은 기간**을 유지한다(90일·30일 총계,
키워드 TOP 10, 웹문서 TOP 5, 사이트 진단 색인/수집제한/색인제외, 수집 현황 일별 표본).
2026-09 회차(`searchadvisor-2026-09.md`)가 그 형식이다.

## 커밋 여부

**커밋해도 된다.** 두 리포트 모두 고객을 식별할 수 있는 정보(이름·연락처·문의 내용)가 없고
집계 수치(조회수·클릭수·전화 연결 건수 등)만 담긴다 — `docs/oplog`가 커밋을 금지하는 이유
(개인 식별 가능성)와는 다른 상황이다. 실제로 `docs/gsc-raw`·`docs/ga4-raw`도 같은 판단으로
이미 저장소에 커밋돼 있다(`git ls-files docs/gsc-raw docs/ga4-raw`로 확인 가능).

주의할 건 **용량**뿐이다. 스마트플레이스 리포트가 일별 상세까지 내려받아지면 파일이 커질 수
있으니, 월별 집계 수준으로 내려받고 원 파일이 지나치게 크면(수 MB 이상) 요약만 남기고 원본은
로컬에만 둔다.

## 실행 절차

1. 매월 1회, 가능하면 월초에 지난달 데이터를 내려받는다(GSC·GA4 루틴과 같은 주기로 맞추면
   `seo-preflight.mjs` 라운드에서 함께 보기 편하다).
2. 파일명 규칙대로 저장 후 커밋한다(서치어드바이저는 화면 수치를 `.md`로 옮겨 적는다 — 위 표 참조).
3. 네이버 검색 노출·전화/예약 전환에 뚜렷한 변화가 있으면
   `docs/proposals/` 새 라운드나 `docs/geo-visibility/`처럼 별도 분석 문서에서 인용한다 —
   이 디렉토리 자체는 원시 데이터 창고이지 분석 문서가 아니다.
