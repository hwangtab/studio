# 전환 개선 설계 — 계측 복구와 오퍼 정합

작성일: 2026-07-14
근거: GSC/GA4 실측(최근 90일, 봇 1,999세션 제외) + PM 패널 8인 회의 + 코드 검증

## 요약

세 가지를 한다: **①리드 계측 버그 수정 ②지역 글의 잘못 걸린 오퍼 교정 ③정의형 콘텐츠 신규 생산 중단.**

세 가지를 하지 않는다: **브릿지 CTA 위계 뒤집기, 지역 페이지 신규 확장, A/B 테스트.**

이 설계의 상방은 크지 않다. 정직하게 말하면 ②의 대상 트래픽 자체가 작다. 그러나 ①은 지금 모든 판단의 근거가 되는 유일한 지표가 오염돼 있다는 문제이고, ②는 "명백히 틀린 것이 걸려 있다"는 사실만으로 정당화된다.

## 배경 — 확인된 사실

| 사실 | 수치 | 검증 |
|---|---|---|
| 사이트 전체 전환율 | 12,031세션 → 96리드 = 0.80% | GA4 |
| 리드의 91%가 카카오톡 클릭 | 87/96, 유니크 사용자 68명 | GA4 |
| 카톡 클릭은 대부분 실제 대화로 이어짐 | — | 운영자 확인 |
| 한국어 스토리는 트래픽 83%인데 전환 0.40% | 9,267세션 → 37리드 | GA4 |
| 고트래픽 정의형 글은 전환 0 | 6편 1,020세션 → 리드 0 | GA4 |
| 정의형 검색 질의는 제로클릭 | CTR 0.19% (상업 3.19%) | GSC |
| 매출은 연습실 월계약과 녹음/믹싱이 반반 | — | 운영자 확인 |
| 연습실 공실 여유 있음 (2개 이상) | — | 운영자 확인 |

### 폐기된 오해 (분석 과정에서 스스로 만든 것)

- **"브릿지 없는 글에 브릿지를 깔면 전환이 오른다"** — 거짓. 리드 0인 정의형 6편은 **이미 전부 브릿지를 달고 있고**, 하단 고정바·글끝 CTA까지 카톡 접점이 3개다. 1,020세션에 리드 0. CTA 문제가 아니라 수요 부재다.
- **"브릿지 있음 0.21% vs 없음 0.47%"** — 무효. `storyAutoFallback.ts`의 `SERVICE_BY_CATEGORY = { instrument: 'practice' }`가 악기 카테고리 글에 브릿지를 빌드 타임에 자동 주입하므로, 마크다운 grep으로 만든 대조군에 브릿지 보유 페이지가 섞여 있었다.
- **"서비스 페이지가 10~25배 잘 전환된다"** — 과장. 리드를 이벤트 발생 페이지로 세고 분모는 랜딩 세션을 써서 생긴 오류. 랜딩 귀속으로 재계산하면 `/ko/practice-room`은 6.14%가 아니라 **4.4%(18/408)**이고, pricing 9.7%·lesson은 각각 리드 3건·2건짜리 극소표본이다. 신뢰구간이 좁은 것은 practice-room 하나뿐이다.

## 결정 1 — 리드 계측 버그 수정 (단독 배포)

### 문제

`components/common/ContactCTA.tsx:47,50` — 비한국어 로케일에서 primary 버튼의 목적지는 `/contact`인데 발화하는 이벤트는 `lead_click_kakao`다.

```ts
const primaryHref = isKorean ? siteConfig.contact.kakaoUrl : getLink('/contact');
...
trackLeadEvent('lead_click_kakao', { ... cta_id: isKorean ? 'contact_cta_primary_kakao' : 'contact_cta_primary_contact' });
```

즉 **"문의 페이지로 이동"이 "카톡 리드"로 집계된다.** 이 사업의 유일하게 신뢰 가능한 지표인 "카톡 87건" 위에 모든 판단이 서 있는데, 그 앵커가 오염돼 있다.

영향은 영어 세그먼트에 집중된다. `/en/*` 랜딩 100세션에서 리드 9건(9.0%)이 나와 사이트 최고 전환율로 보이지만, 뜯어보면 폼 제출 2건(그중 1건은 진단 테스트) + 카톡 클릭 4건 + 나머지는 이 버그일 가능성이 있다. **보정해도 영어권은 사이트 평균의 5~9배로 보이지만, 정확한 값은 버그를 고쳐야 나온다.**

부수적으로 `ContactCTA`의 `/contact` secondary 버튼(:89)과 `InlineServiceCallout`의 서비스 페이지 링크에는 추적이 아예 없어, "스토리 독자가 서비스 페이지로 넘어가는가"가 관측 불가능하다.

### 변경

1. `LeadEventName`에 `lead_click_contact` 추가. 비한국어 primary 버튼과 `/contact` secondary 버튼이 이 이벤트를 발화한다. **`lead_click_kakao`와 분리한다.**
2. `InlineServiceCallout`의 서비스 페이지 링크에 추적 부착. 단 이벤트명은 **`micro_click_service`**로 하고 리드 이벤트 집합에 넣지 않는다 — 유일하게 신뢰 가능한 리드 지표를 마이크로 전환으로 희석하지 않는다.
3. 영어 로케일에서 primary·secondary 버튼이 **둘 다 `/contact`를 가리키는 중복**을 정리한다(버튼 1개).

### 성공/실패

- **성공**: 배포 후 2주간 `lead_click_kakao`와 `lead_click_contact`가 분리 집계되고, `micro_click_service`가 GA4에 찍힌다. 새 카톡 기준선(주당 N건)이 확정된다.
- **주의**: 지표 정의가 바뀌므로 **카톡 리드가 87보다 줄어든다.** 이 하락을 결정 2의 탓으로 오독하지 않으려면 반드시 단독 배포하고 2주 기준선을 굳힌 뒤 다음으로 넘어간다.
- **중단 조건**: 없음. 버그 수정이다. 다만 `micro_click_service`를 리드로 승격하고 싶어지면 그 자체가 실패 신호다.

## 결정 2 — 지역 글의 오퍼 정합 (결정 1 배포 2주 후)

### 문제

`lib/storyAutoFallback.ts:17` — `PRICING_BY_CATEGORY.region = 'recording-pro'`
`lib/inlineDirectives.ts:92,100` — `decideAutoFallback`은 하나만 주입하며 **price가 service보다 먼저 반환된다.**

결과: **"연신내 연습실 월세"로 들어온 사람의 본문 한가운데에 시간당 10만원 보컬녹음 가격표가 꽂힌다.** 그리고 지역 글은 구조적으로 연습실 브릿지를 받을 수 없다.

구매 의도가 가장 순수한 페이지들이 유일하게 틀린 상품을 제안받고 있다.

### 대상 — 라이브 `region` 스토리 48편은 성격이 둘로 갈린다

| 그룹 | 편수 | 예시 | 올바른 오퍼 |
|---|---|---|---|
| 실제 상권 연습실 | 26 | practice-room-{연신내, 불광, 응암, 구파발, 삼송, 덕양, 녹번, 역촌…} | **연습실**(`service:practice`) |
| 광역 허브 | 22 | seoul1, gyeonggi1, busan1, daegu1, jeju1… | **녹음**(현행 `recording-pro` 유지) |

부산 검색자에게 서울 연습실은 무의미하지만 원격 믹싱·데이록 녹음은 유효하다. 따라서 **일괄 변경이 아니라 분기**한다. `lib/regionHubSlugs.ts`의 `isRegionHub(slug)`가 이미 존재하고 `lib/stories.ts`가 이미 임포트하고 있다.

### 변경

`region` 카테고리의 자동 fallback을 슬러그로 분기한다.
- `isRegionHub(slug) === false` (= 실제 상권 연습실 26편) → `service:practice`
- `isRegionHub(slug) === true` (= 광역 허브 22편) → 현행 `price:recording-pro` 유지

`storyAutoFallback`의 API가 categoryKey만 받으므로 슬러그를 함께 받도록 확장하거나, 호출부(`lib/stories.ts`)에서 분기한다. 기존 테스트(`lib/inlineDirectives.test.ts`, `lib/storyAutoFallback.test.ts`) 갱신 필요.

### 성공/실패

- **1차 지표는 리드가 아니라 `micro_click_service`다.** 12주 후 판정: 실상권 지역 스토리 → `/practice-room` 클릭률 **≥ 2%**.
- **2차**: 12주간 실상권 지역 스토리 랜딩 리드가 이전 90일 대비 **감소하지 않을 것**.
- **리드로 개선을 "증명"하려 들지 않는다.** 주당 리드 7.5건, 포아송 노이즈 ±2.7건에서 스토리 전환율 0.40%의 50% 개선을 검출하려면 12.6개월이 걸린다. 이 규모에서 A/B는 의사결정 도구가 아니라 회피 도구다.
- **중단 조건**: 배포 후 전체 카톡 클릭의 4주 이동평균이 새 기준선 대비 **-35% 이하**로 내려가면 즉시 롤백. (-20%는 노이즈에 정기적으로 걸리므로 오경보 장치다.)

## 결정 3 — 정의형 콘텐츠 신규 생산 중단

정의형 질의는 90일 80클릭(전체 8,788클릭의 0.9%), 리드 0. 구글 AI 개요가 답을 대신하는 제로클릭 SERP다. 신규 생산의 기회비용은 사실상 0이다.

**기존 1,700편은 삭제하지 않는다.** 유지비가 0이고, 무권위 도메인(1~3위 노출 0.16%)의 상업 페이지를 평균 6.2위에 붙들고 있는 것이 이 코퍼스의 토픽 신호일 가능성은 반증되지 않았다. 반증 실험의 회복 비용이 비대칭적으로 크다. 측정 못 하는 것을 0으로 쓰지 않는다.

**"상업 의도 콘텐츠로 전환"은 지금 승인하지 않는다.** 근거가 `recording-price1`(리드 4건)과 `seoul1`(3건) 두 편뿐이고, 어느 채널에서 만들 것인지가 아래 미해결 쟁점 해소 전에는 정해지지 않는다.

## 하지 않기로 한 것

| 항목 | 폐기 사유 |
|---|---|
| 브릿지 CTA 위계 뒤집기 (카톡→서비스 페이지를 1차로) | 대상 6편에 브릿지가 이미 있고 리드 0. 게다가 링크 목적지(`/pricing`·`/practice-room`)의 1차 CTA도 결국 카카오톡이라, 마찰을 줄이는 게 아니라 한 단계 늘린다. 상방은 주당 +0.24건(추정)으로 포아송 노이즈에 완전히 묻힌다. |
| 지역 페이지 신규 확장 | "연신내·삼송·덕양이 검증됨"의 실체는 각각 리드 1~2건이다. 1/7의 95% 신뢰구간은 대략 [2.6%, 52%] — 아무것도 모른다는 뜻. 실상권 LP는 이미 26편 있다. 27번째를 만들기 전에 26편의 오퍼부터 고친다(결정 2). |
| 모든 형태의 A/B 테스트 | 스토리 CVR 0.40%, 103세션/일에서 상대 +50% 검출에 arm당 약 19,500세션 → 12.6개월. 검출 가능한 최소 효과가 사실상 "2배"다. |
| 한국어 "오시는 길" 라벨 교정 | 문자열부터 사실이 아니었다(`actions.location`은 "위치"). 그리고 한국어 폼 실제 문의는 90일 0건인데 카톡은 87건이다. 카톡으로 갈 사람을 전환되지 않는 폼으로 새게 할 위험만 있고, 그 손실은 이 표본에서 영원히 검출되지 않는다. |
| 영어권 B2B(다중 룸 장기 대관)를 전략 축으로 삼기 | 팔 수 있는 상품이 아니다. `pages/api/llms.ts`와 `data/pricing.ts`는 녹음실을 단수로 기술한다. 문의는 "녹음실 4개 × 13일"이었다. n=1에 곱셈을 얹어 전략을 세우지 않는다. |
| `%%phone%%` 처리 | 패널 주장("86개 파일에서 빈칸으로 렌더")은 **거짓**. 라이브 프로덕션에서 "전화 010-4255-7893"으로 정상 치환됨을 확인했고, `lib/factTokens.ts`의 `applyFactTokens`가 처리한다. |

## 미해결 쟁점

1. **네이버가 측정 밖에 있다.** 가장 잘 전환되는 `/ko/practice-room` 유입의 **32%가 네이버**다(m.search.naver.com 105 + naver/organic 25 / 총 408). 구글은 57%. 이 사업은 은평구 연신내의 지역 사업체이고 주력 상품은 월 36만원 연습실 월계약인데, 우리가 보는 검색 데이터는 GSC(구글)뿐이다. 레포에 `docs/naver-blog/`가 이미 있다 — 운영자는 네이버에 콘텐츠를 발행하고 있는데 그 성과가 어떤 분석에도 잡히지 않는다. **네이버 서치어드바이저 연동을 별도 과제로 검토해야 한다.**
2. **영어 세그먼트의 진짜 크기.** `/en/*` 100세션 → 9리드(9.0%)는 사이트 최고지만 결정 1의 버그로 오염돼 있다. 배포 후 4주 재측정 전에는 판단하지 않는다. 단 `/en/stories/korean-practice-room-booking-english` 한 편이 22세션에서 리드 6건을 만든 것은 사실이고, 유입원은 챗GPT다. **국내 거주 영어권의 연습실 수요**라는 가설이 성립하면 이건 공급 가능한 상품이다(공실 여유 확인됨).
3. **결제 전환율.** 리드 96건 중 실제 결제 건수를 기록하지 않고 있다. 연습실 1년 계약(432만원)과 마스터링(10만원)이 지금 똑같이 "리드 1건"이다. 대시보드를 만들 규모가 아니므로(주 7.5건) **스프레드시트 한 장에 손으로 기록**한다.

## 실행 순서

2. 결정 2 배포 → 12주 후 `micro_click_service` 기준 판정

4. 병행: 네이버 측정 수단 확보 검토, 결제 기록 시작
