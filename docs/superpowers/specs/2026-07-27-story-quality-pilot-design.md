## 0. 문제 진단

파일럿 2편을 정독한 결과, 기존 "탈템플릿" 작업으로 들어간 1인칭 섹션은 **형식만 1인칭이고 내용은 일반론**이다.

| 파일 | 섹션 | 현재 상태 |
|---|---|---|
| practice-room-startup1 | "연습실을 직접 운영해온 사람으로서 — 창업 전 꼭 짚을 세 가지" | "최소 3사 견적을 받고" — 본인이 몇 사에서 얼마 받았는지 없음 |
| practice-room-startup1 | "창업 전에 먼저 살아보세요" | 입주 상품 세일즈. 운영 관찰 데이터는 없음 |
| plugins1 | "15년 믹싱하며 정리된 플러그인 철학" | "저도 실제 세션에서 쓰는 EQ·컴프는 손에 꼽아요" — 무엇인지 안 나옴 |
| plugins1 | "Studio NOL 보컬 믹싱에서 자주 쓰는 플러그인 조합 3가지" | 체인은 구체적이나, 실제 사용 체인인지 미검증 (인터뷰 확인 대상) |

경쟁사가 그대로 복제할 수 있는 문장들이므로 아직 E-E-A-T 해자가 아니다.

동시에 AI 티가 뚜렷하다 — 볼드 라벨+콜론 병렬 5연속, 불릿 5개 기계적 나열, "차원이 다릅니다"류 관용 마무리, 균일한 문장 길이.

**따라서 이 작업은 두 개의 별개 작업이다**: 내용을 채우는 *전문화*(사실 추가)와 문체를 고치는 *윤문*(사실 불변). 섞으면 어느 쪽도 검증할 수 없다.

## 1. 확정 사항 (브레인스토밍 결과)

| 항목 | 결정 | 근거 |
|---|---|---|
| 범위 | 파일럿 2편 (`practice-room-startup1`, `plugins1`) | 1,576편 판돈을 검증 없이 걸지 않는다 |
| 소재 조달 | **인터뷰 방식** — 질문지 → 황경하 답변 → 답변만으로 서술 | 원본 사실은 지어낼 수 없다. 날조 리스크 제거 |
| 기준 문체 | **"~습니다" 유지** + `content-guidelines.md` 톤 규정 갱신 | 실물 1,576편이 이미 이 문체. 가이드가 현실과 어긋나 있었음 |
| 윤문 범위 | **산문 세그먼트만 추출** 후 윤문, 제자리 병합 | 두 파일 모두 14K자대 → 통짜 입력 시 strict 자동 승급 + 구조 훼손 위험 |
| 공정 순서 | 심화 → 윤문 | 역순이면 심화 텍스트가 AI 티를 달고 들어와 윤문을 두 번 돌려야 함 |

**티어 문서 수치 정정**: `story-tier-flagship-2026-07.md`는 practice-room-startup1을 5,858자,
plugins1을 4,882자로 기재하나 실측은 각각 14,841자 / 14,256자다(프론트매터 포함).
그 사이 심화 작업이 반영된 결과로 보인다. 티어 문서 글자수 열은 파일럿 종료 시 갱신한다.

## 2. 공정

```
Stage 0  진단      → 산문/비산문 세그먼트 분해 + 일반론 1인칭 주장 목록화
Stage 1  인터뷰    → 편당 6~10문항 질문지 → 황경하 답변 수령
Stage 2  심화      → 답변만으로 섹션 교체·보강
Stage 3  윤문      → 산문 세그먼트 추출 → humanize-korean(fast) → 병합
Stage 4  검증      → 게이트 6개
Stage 5  판정      → diff 리뷰 → 커밋 → 회고 → 확대 여부 결정
```

### Stage 0 — 진단

파일별로 산출:

1. **세그먼트 맵** — 각 줄을 `prose` / `structure`로 분류. `structure`는 윤문 대상에서 제외한다.
2. **일반론 1인칭 주장 목록** — "1인칭 화자가 등장하는데 구체 사실이 없는" 문장. Stage 1 질문지의 입력.
3. **AI 티 사전 스캔** — Stage 3 윤문 전후 비교용 베이스라인.

### Stage 1 — 인터뷰

질문지는 파일당 하나의 마크다운으로 만들어 사용자에게 전달한다. 문항 구조:

```
### Q3. 방음 시공 견적 (practice-room-startup1.md:199)
현재 문장: "최소 3사 견적을 받고 STC 등급·차음 자재·시공 방식을 명세서로 비교해야 합니다."
묻는 것  : 실제로 몇 개 업체에서 견적을 받으셨고, 최저-최고 금액 차이가 얼마였나요?
           업체명은 안 밝혀도 됩니다. 연도와 실 개수만 있으면 충분합니다.
답변     : (여기에 적어주세요)
모르거나 공개 곤란하면: "패스" — 해당 1인칭 주장을 삭제하고 일반론으로 격하합니다.
```

**"패스" 처리 규칙**: 답변이 없는 항목은 지어내지 않는다. 세 가지 중 하나로 처리한다.
- (a) 1인칭 주장을 삭제하고 일반 서술로 격하
- (b) 섹션 자체를 제거
- (c) 외부 출처로 대체하고 1인칭 표지를 뗀다

### Stage 2 — 심화

- **철칙: 인터뷰 답변에 없는 사실은 한 줄도 쓰지 않는다.** 추론·보간·"그럴듯한 살 붙이기" 금지.
- 기존 일반론 1인칭 섹션을 답변 기반 서술로 교체한다. 새 섹션을 덧붙이기보다 교체를 우선한다(분량 인플레 방지).
- **목록 AI 티 정리도 이 단계에서 함께 한다.** Stage 3 윤문이 목록을 다루지 않으므로,
  볼드 라벨+콜론 5연속·불릿 5개 기계적 나열 같은 패턴은 여기서 손으로 푼다.
  대상은 심화 섹션에 국한하지 않고 해당 파일의 본문 목록 전체다. 단 표·FAQ·howTo는 건드리지 않는다.
- 목표 순증: 편당 800~1,500자.
- 정본 사실 준수: 성우 10만원/시간, 전화번호는 `%%phone%%` 토큰만, 보컬·악기 레슨 없음(프로듀싱 레슨만),
  연신내역 4번 출구. 상세는 `lib/factGuards.ts`.
- 제목(H2/H3)은 변경하지 않는다 — 본문 내 앵커 링크가 깨진다.

### Stage 3 — 윤문

**추출 제외 대상** (= `structure` 세그먼트):

- 프론트매터 전체 (`---` 사이 YAML: title·summary·faq·howTo·tags 등)
- 표 (`|`로 시작하는 줄), 코드블록(``` 펜스 내부)
- 이미지 (`![...]`), 링크 전용 줄
- `%%...%%` 디렉티브 (`%%service:lesson%%`, `%%phone%%` 등)
- 수평선 `---`, H1~H4 제목 줄
- 불릿/번호 목록 — **1차 파일럿에서는 제외**한다. 목록 항목은 문장 경계가 모호해 마커 병합 리스크가 크다.
  목록의 AI 티(볼드 라벨+콜론 5연속 등)는 Stage 2 심화 단계에서 손으로 정리한다.

**병합 프로토콜**:

1. 산문 블록마다 `<<<SEG:001>>>` 형식 마커를 앞에 붙여 단일 텍스트로 결합.
   블록 단위는 **빈 줄로 구분되는 연속 산문 줄 묶음**이며, 위 제외 대상이 하나라도 섞인 블록은 통째로 제외한다
2. humanize-korean fast 모드에 입력. "마커 줄은 절대 수정·삭제 금지" 지시를 함께 전달
3. 결과에서 마커로 재분할
4. **마커 개수·순서가 입력과 불일치하면 병합을 중단**하고 수동 처리로 전환. 조용한 어긋남을 허용하지 않는다
5. 원본 파일의 해당 줄 범위를 윤문 결과로 치환

윤문 스킬의 `_workspace/`는 리포를 오염시키므로 스크래치패드를 cwd로 실행한다.

### Stage 4 — 검증 게이트

| # | 게이트 | 방법 | 실패 시 |
|---|---|---|---|
| 1 | 콘텐츠 품질 | `npm run content-check` | 수정 후 재실행 |
| 2 | 정본 사실 | `npx jest content/` (factGuards·ctrTargets·storyLinks·serviceBridge) | 수정 후 재실행 |
| 3 | 구조 무결성 | 프론트매터 키·표 행·링크·퍼센트 디렉티브(`%%service:lesson%%` 등) 개수 before=after | 병합 롤백 |
| 4 | **사실 출처 대조** | 심화 섹션의 사실 주장을 1건씩 인터뷰 답변에 매핑한 표 작성 | 근거 없는 문장 삭제 |
| 5 | 윤문 품질 | humanize 등급 A~B, 변경률 5~30% | 등급 C 이하 → strict 재실행 |
| 6 | 빌드·육안 | `npm run build` 1회 + `git diff` 전량 리뷰 | — |

게이트 4가 이 설계의 핵심이다. 1~3·6은 기계가 잡지만 **날조는 기계가 잡지 못한다.**

### Stage 5 — 판정

1. 두 편의 diff를 사용자에게 제시하고 승인받은 뒤 커밋
2. 회고 기록: 편당 소요시간·도구 호출 수·인터뷰 왕복 횟수·품질 등급
3. 회고를 근거로 F15 나머지 13편 확대 여부와 편당 예산을 결정
4. `docs/content-guidelines.md` 톤 규정 갱신 — "~해요 권장 / ~습니다 금지"를 실물에 맞게 정정

## 3. 성공 기준

- [ ] 심화 섹션의 사실 주장 **100%**가 인터뷰 답변에 출처를 가진다 (게이트 4 대조표로 증명)
- [ ] 구조 무결성 100% — 프론트매터·표·링크·디렉티브 손실 0
- [ ] 게이트 1·2·6 전부 통과
- [ ] humanize 등급 A~B, 변경률 5~30%
- [ ] 편당 소요시간·비용이 기록되어 확대 판단에 쓸 수 있다

## 4. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 인터뷰 답변 부실 | 심화 불가 | "패스" 처리 규칙 (a)/(b)/(c) 적용. 지어내지 않는다 |
| 윤문이 정본 수치·토큰 변조 | 팩트가드 실패, SEO 손상 | 게이트 2·3. `%%...%%`는 추출 제외 |
| 마커 유실로 병합 어긋남 | 본문 손상 | 개수·순서 검증 후 불일치 시 중단 |
| 제목 변경으로 앵커 링크 파손 | 내부 링크 깨짐 | 제목은 추출·수정 대상에서 제외 |

| 심화가 분량 인플레로 흐름 | 가독성 저하 | 덧붙이기 대신 교체 우선, 순증 1,500자 상한 |
