# 콘텐츠 작성 및 관리 가이드라인 (2025.02.03)

이 문서는 스튜디오 놀 사이트의 콘텐츠(Story, Docs 등)를 작성할 때 준수해야 할 규칙을 정리한 것입니다.

## 1. 이미지 사용 규칙 (Image Guidelines)

새로운 콘텐츠를 작성할 때, 굳이 새로운 이미지를 찾거나 구매하려 애쓰지 않습니다. 이미 서버에 업로드된 고품질 에셋들을 적극적으로 재활용합니다.

*   **기본 원칙**: `public/images` 폴더 내에 있는 기존 파일 중 분위기에 맞는 것을 자유롭게 선택하여 사용합니다.
*   **파일 경로**: 마크다운 내에서 `/images/파일명.jpg` 형태로 참조합니다.
*   **선택 기준**:
    *   완벽하게 내용과 일치하지 않아도 됩니다. (예: '마이크' 글에 '콘솔' 사진 ok)
    *   글의 **전반적인 분위기(Mood)**와 어울리는 고해상도 이미지를 우선합니다.
*   **주요 에셋 목록**:
    *   **스튜디오 전경**: `studio1.jpg` ~ `studio5.jpg`
    *   **장비/하드웨어**: `hardware1.jpg` ~ `hardware8.jpg`, `console.jpg`
    *   **녹음/세션**: `recording1.png` ~ `recording17.png`
    *   **기타**: `service1.jpg` ~ `service8.jpg`

## 2. 글쓰기 톤 & 매너 (Tone & Manner)

기존의 딱딱한 매뉴얼/강의 형식을 탈피하고, 독자에게 친근하게 다가가는 **'휴머나이징(Humanizing)'** 전략을 따릅니다.

*   **페르소나 (Persona)**:
    *   **친절한 멘토 선배**: 권위적인 선생님이 아니라, 먼저 경험해본 선배가 옆에서 조곤조곤 설명해주는 느낌.
    *   **따뜻한 공감**: 독자가 느낄 어려움이나 좌절감에 공감해 줍니다. ("처음엔 다들 어려워해요", "저도 실수했던 기억이 나네요")
*   **어투 변경**:
    *   **금지**: "~합니다", "~것입니다", "~살펴보겠습니다" (딱딱한 개조식/번역투)
    *   **권장**: "~해요", "~거든요", "~일까요?", "~해볼까요?" (부드러운 구어체)
*   **쉬운 비유 (Analogy)**:
    *   전문 용어는 반드시 일상적인 개념에 빗대어 설명합니다.
    *   *예시: 헤드룸 → "천장 높이", 오디오 인터페이스 → "통역사", 룸 모드 → "방의 거짓말"*

## 3. 콘텐츠 구조 (Structure)

*   **히어로 이미지 자동 처리**:
    *   본문의 **가장 첫 번째 이미지**는 자동으로 페이지 상단(Hero Section) 배경으로 사용됩니다.
    *   시스템이 이를 감지하여 본문 내용에서는 해당 이미지를 **자동으로 숨김 처리**합니다. (중복 노출 방지)
    *   따라서 작성자는 첫 줄에 대표 이미지를 삽입하고, 바로 글을 시작하면 됩니다.

## 4. 날짜 설정 규칙 (Date Setting Rules)

시리즈물의 순서를 보장하기 위해 작성 날짜(`date`)를 전략적으로 설정합니다.

*   **순차적 날짜 부여**: 이전 편의 날짜보다 **하루 뒤**로 설정하여 리스트에서의 순서를 강제합니다.
    *   *예시: 11부(11월 21일) → 12부(11월 22일) → 13부(11월 23일)*
*   **미래 날짜 허용**: 실제 작성일(Today)보다 미래의 날짜라도, 시리즈 정렬을 위해 미래 날짜를 사용하는 것을 허용합니다.
*   **Frontmatter**: 마크다운 상단 `date` 필드에 `YYYY-MM-DD` 형식으로 기입합니다.

## 5. 작업 프로세스 (Work Process)

믹싱 강좌 콘텐츠는 무에서 유를 창조하는 것이 아니라, 기존의 방대한 매뉴얼을 기반으로 제작됩니다.

1.  **소스 문서 (Source Material)**:
    *   `/docs/오디오 믹싱 메뉴얼.md` 파일이 원본 교과서(Bible)입니다.
    *   이 문서의 챕터 순서대로 강좌를 진행합니다. (예: 매뉴얼 5,6장 → 강좌 12부)
2.  **가공 단계 (Processing)**:
    *   매뉴얼의 내용을 정독하여 핵심 내용을 요약합니다.
    *   **Humanizing**: 요약된 건조한 텍스트를 위에서 정의한 '멘토 페르소나'로 리라이팅합니다.
3.  **파일 생성**:
    *   `content/stories/` 폴더에 `mixing{N}.md` 형식으로 파일을 생성합니다.

## 6. 기술 아키텍처 (Technical Architecture)

마크다운 파일이 웹사이트에 배포되는 기술적 흐름(Data Flow)은 다음과 같습니다. 인수인계 시 필독 바랍니다.

1.  **Markdown File (`content/stories/*.md`)**:
    *   작성자가 커밋한 원본 데이터입니다. Frontmatter(제목, 날짜 등)와 Body(본문)로 구성됩니다.
2.  **Build Time Parsing (`lib/stories.ts`)**:
    *   Next.js 빌드 시점에 `fs` 모듈이 폴더 내의 모든 md 파일을 읽습니다.
    *   `gray-matter`: Frontmatter를 파싱하여 메타데이터 객체로 변환합니다.
    *   `remark`: 마크다운 본문을 HTML로 변환(serialization)합니다.
    *   **Image Stripping**: `lib/stories.ts`에는 첫 번째 이미지가 Hero로 쓰일 경우 본문에서 제거하는 로직이 포함되어 있습니다.
3.  **Static Generation (`getStaticProps`)**:
    *   `pages/stories/[id].tsx`의 `getStaticProps`가 실행됩니다.
    *   파싱된 데이터는 **JSON 형태**로 직렬화되어 페이지의 `props`로 전달됩니다.
    *   배포 시 이 JSON 데이터는 HTML과 함께 빌드 아티팩트에 포함됩니다.
4.  **Client-Side Rendering**:
    *   사용자 브라우저에서는 사전 빌드된 HTML과 JSON 데이터를 받아 `MarkdownRenderer` 컴포넌트를 통해 화면에 그려냅니다.
    *   이미지 파일은 자동으로 최적화되므로 원본 화질을 유지합니다.
    *   캡션은 `MarkdownRenderer`에서 자동으로 `alt` 태그나 별도의 디자인으로 처리되므로 마크다운 내에서 텍스트로 적지 않습니다.

## 7. 심층 콘텐츠 작성 가이드 (Deep & Sincere Writing Guidelines)

단순한 정보 전달을 넘어, 독자가 '멘토에게 1:1 레슨을 받는 듯한' 깊이와 진정성을 담아야 합니다.

### 7.1. 분량과 깊이 (Depth & Length)
*   **피상적인 요약 금지**: "A는 B입니다" 식의 사전적 정의나 짧은 요약글(50줄 미만)을 지양합니다.
*   **충분한 설명**: 하나의 개념을 설명하더라도 '왜(Why)' 중요한지, 현장에서는 어떻게 쓰이는지 충분히 풀어서 설명합니다. (최소 100줄 이상 권장)
*   **철학적 접근**: 기능 설명 이전에 그 기능이 음악적으로 어떤 의미를 갖는지 통찰(Insight)을 제공합니다.
    *   *Bad*: "EQ는 주파수를 조절합니다."
    *   *Good*: "EQ는 소리를 조각하는 칼입니다. 불필요한 부분을 덜어내어 본질을 드러내는 과정이죠."

### 7.2. 진정성 있는 톤 (Sincere Mentor Tone)
*   **실패 경험 공유**: "저도 처음엔 이렇게 실수했습니다"와 같이 자신의 취약점을 드러내며 공감대를 형성합니다.
*   **권위와 겸손의 조화**: 전문적인 지식을 전달하되, 가르치려 들지 않고 옆에서 조언해주는 선배의 태도를 유지합니다.
*   **구체적인 묘사**: 소리를 시각적, 촉각적 언어로 표현합니다.
    *   *단단하다(Solid), 진흙 같다(Muddy), 헐렁하다(Loose), 쫀쫀하다(Tight), 공기 반 소리 반(Airy)*

### 7.3. 실전성 강화 (Practicality)
*   **구체적인 액션 아이템**: 독자가 글을 읽고 바로 따라 해볼 수 있는 구체적인 행동 지침을 제공합니다.
    *   예: "지금 바로 모노 버튼을 눌러보세요.", "눈을 감고 페이더만으로 10분 동안 믹스해보세요."
*   **현실적인 조언**: 교과서적인 이야기보다, 열악한 홈레코딩 환경이나 저가 장비에서의 현실적인 대처법을 다룹니다.
    *   예: "방음이 안 된다면 이불을 뒤집어쓰고 녹음해보세요."

### 7.4. 구성 전략 (Structure Strategy)
1.  **공감과 문제 제기**: 초보자들이 겪는 어려움으로 시작 ("왜 내 믹스는 답답할까?").
2.  **비유를 통한 개념화**: 어려운 기술 용어를 쉬운 일상 비유로 치환 (컴프레서 = 자동 볼륨 조절기).
3.  **핵심 원리 심화**: 원리를 깊이 있게 파고듦 (파라미터의 상호작용 등).
4.  **실전 적용 및 팁**: 바로 써먹을 수 있는 비기(Secret Sauce) 공개.
5.  **철학적 마무리**: 기술을 넘어 음악을 대하는 태도로 마무리.
