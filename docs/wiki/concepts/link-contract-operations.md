# 링크 계약 운영 가이드

고객 이름·연락처를 모르는 채로, 카카오톡에 **링크 하나만 보내서** 믹싱·마스터링(또는 음원 제작) 용역 계약을 맺는 방법과 그 뒤 운영자가 할 일.
코드가 정본이다. 숫자·문구가 바뀌면 아래 출처 파일을 다시 확인할 것. (2026-10-20 기준)

## 1. 언제 쓰나

- 카톡으로 믹싱·마스터링 문의가 왔는데 **이름·연락처·이메일을 아직 모를 때**. 일반 계약은 작성 폼에 의뢰인 정보를 먼저 넣어야 하지만, 링크 계약은 **고객이 서명 화면에서 직접 적는다**.
- 운영자 쪽에서는 고객 칸을 비워 두고(`client_phone = ''`이 링크 계약의 판정) 발송하면, 메일 없이 서명 링크만 생긴다. 이 링크를 카톡으로 보낸다. (출처: [open-link.ts](../../../lib/contracts/production/open-link.ts), [CLAUDE.md](../../../CLAUDE.md) "링크 계약")
- 믹싱·마스터링(`mixmaster`)뿐 아니라 제작 계약(싱글·EP·정규)도 같은 방식으로 만들 수 있다.

## 2. 만드는 두 가지 방법

| 방법 | 어떻게 |
|---|---|
| (a) Claude에게 요청 | "믹싱 마스터링 N트랙 계약 링크 만들어줘"라고 하면 `npx tsx scripts/contract-link.ts create --kind mixmaster --tracks N --memo "카톡 홍길동" --yes`를 돌려 링크를 돌려준다. `--yes` 없이는 **미리보기만** 나온다 — 금액·기한을 보고 맞으면 `--yes`. |
| (b) 관리자 화면 | 관리자 > 제작·믹싱 계약 > 새 계약 작성 폼에서 **"의뢰인 정보를 아직 몰라요"** 체크 → 조건 입력 → 저장 → 상세에서 **서명하고 발송** → **서명 링크 복사** → 카톡에 붙여넣기. |

- 두 방법은 같은 코드(`lib/contracts/production/service.ts`)를 쓴다. 발송 = **스튜디오 대표 서명**이다. 스크립트로 발송하면 서명 기록의 서명자가 `CONTRACT_ACTOR`(기본 kyungha) + " (scripts/contract-link.ts)"로 남는다.
- `--memo`는 "누구에게 보낸 링크인지"를 계약 제목 끝에 남긴다(관리용, 고객 화면에는 안 나온다). 고객 이름을 모르니 목록에서 구별하려면 꼭 적는다.
- 스크립트 옵션: `--total N`(정가와 다른 금액, 부가세 포함) · `--first-days N`(믹싱 1차 영업일) · `--weeks N`(최종 주) · `--deposit-days N`(입금 기한) · `--song 제목` · `--title`. (출처: [contract-link.ts](../../../scripts/contract-link.ts))
- 스크립트는 운영 DB에 로그인된 Turso CLI(`~/.turso/turso`)로 붙는다. 토큰은 만료 1일짜리를 그때그때 만들고 파일에 쓰지 않는다.

## 3. 기본 조건

믹싱·마스터링 계약의 기본값은 `terms.ts`에서 나온다. **사이트 정가와 같은 금액**이다(`data/pricing.ts`).

| 항목 | 기본값 | 출처 |
|---|---|---|
| 범위 | 믹싱 N트랙 이하 + **싱글 마스터링 1곡** | `applyMixMasterTracks` |
| 믹싱 가격 구간 | 10트랙 이하 20만원 / 11~30트랙 35만원 / 31트랙 이상 50만원 | `mixingPriceForTracks`, `pricing.ts` |
| 마스터링 | 싱글 10만원 | `MASTERING_SINGLE_PRICE` |
| 계약금액 | 믹싱 + 마스터링 → 각각 **30만 / 45만 / 60만원**(부가세 포함) | `applyMixMasterTracks` |
| 지급 방식 | **50만원 이하는 일시불**(계약금 = 전액, 잔금 0). 넘으면(60만원) 계약금·잔금 절반씩 | `SINGLE_PAYMENT_MAX`, `splitPayment` |
| 입금 기한 | 체결 후 3일(`--deposit-days`로 변경), 잔금은 7일 | `MIXMASTER_BASE` |
| 납품 기한 | **믹싱 1차 7영업일** 이내, **최종 마스터 2주** 이내 | `firstDeliveryBusinessDays`, `DEFAULT_WORK_WEEKS` |
| 무료 수정 | **믹싱 2회 / 마스터링 1회** (초과 시 회당 믹싱 5만원·마스터링 3만원 별도) | `revisions`, `DEFAULT_EXTRA_REVISION_FEES`, 계약서 제5조 |
| 간주 승인 | 결과물 전달일부터 **7일** 이내 수정 요청이 없으면 그 단계 승인으로 본다 | 제5조 5항 |
| 해지 정산 경계 | 환불 항목 하나. **믹싱 1차를 전달하면 믹싱 몫(정가 비율), 마스터링을 전달하면 전액**을 작업분으로 본다 | `refundSchedule`, 제10조 |

- 계약서에는 "약 N주"가 아니라 **납품 기한이 명시**된다(운영자 요구, 2026-10-20). 되돌리지 말 것.
- 일시불 계약은 계약서·메일·진행 화면이 "계약금·잔금" 대신 "대금 일시불"로 말한다(`depositWordFor`).
- 정가와 다른 금액(할인 등)은 `--total` 또는 작성 폼에서 고친다. 환불 항목 금액도 같이 맞춰진다.

## 4. 고객이 보는 화면

고객은 카톡 링크를 눌러 서명 화면(`/contracts/production/{id}/sign`)에서 아래를 한다.

1. 계약서 본문 읽기.
2. **정보 입력** — 이름(실명)·활동명(선택)·휴대폰·이메일. 이메일은 **확인 칸까지 두 번** 적는다(서명본 PDF가 이 주소로 간다).
3. **동의 체크 2개** — ① "중요 조항 확인"(간주 승인 7일·착수 후 해지 공제·발매 후 포트폴리오 게재 요약, 계약서 제5·10·11조), ② "본인이 계약 당사자임을 확인". (출처: [clauses.ts](../../../lib/contracts/production/clauses.ts), 서명 화면)
4. 서명 후 제출 → 서명본(PDF)이 고객이 적은 이메일로 간다.

### 본인 확인을 하지 않는다 — 그 의미

- 일반 계약은 계약서에 등록된 연락처 **뒷자리 4자리 대조**로 본인 확인을 한다. 링크 계약은 **대조할 번호가 없어 이 확인을 하지 않는다**.
- 서명본 PDF에는 "본인 확인: 연락처 대조 없음 — 스튜디오가 발송한 서명 링크로 서명"이 적힌다. 하지 않은 확인을 기록하지 않는 것이 원칙이다.
- 그래서 **링크는 반드시 그 고객과의 1:1 카톡 대화방에만** 보낸다. 단톡방·SNS 공개 게시 금지. 링크를 받은 사람이 곧 서명자다. 감사 기록(서명 일시·IP·브라우저)은 일반 계약과 같게 남는다.
- 법정대리인은 지정할 수 없다. **미성년 의뢰인은 서명 화면이 막는다** → 미성년이면 링크 계약이 아니라 일반 계약(법정대리인 포함)으로 만든다.

## 5. 체결 후 운영자가 할 일

1. **운영자 알림 메일 확인** — 제목에 **"— 본인 확인 필요"**가 붙은 메일이 온다. 본문에 고객이 적은 이름·연락처가 있고 "카톡 상대와 이름·연락처가 맞는지 확인해 달라"고 적혀 있다. **카톡 대화 상대와 대조**한다. 안 맞으면 계약 상세에서 대응(해지 등).
2. **입금 확인 기록** — 입금은 자동 반영되지 않는다. 입금이 들어오면 계약 상세 진행 기록에 **"입금 확인"**(금액 입력)을 남긴다.
   - 기록하지 않으면 입금 기한 전날 **이미 입금한 고객에게 독촉 안내가 간다.** 그래서 기한 **이틀 전·하루 전**에 상세 화면 "할 일"에 알림이 뜬다. (출처: [ledger.ts](../../../lib/contracts/production/ledger.ts) `buildTodos`)
   - 기한이 지나면 경고, 지체가 `paymentDelayDays`를 넘으면 통지 후 해지 가능(제10조 5항) 안내가 뜬다.
3. **1차 완성본(원본 파일) 수령 기록** — 받으면 "1차 완성본 수령"을 남긴다. 작업 기간(최종 2주)이 계약금 입금과 수령이 끝난 날부터 센다.
4. **결과물 전달 기록** — 믹싱 1차·마스터링을 보낼 때마다 "결과물 전달"(링크 선택)을 남긴다. 기록하면 고객에게 통지 메일이 나가고, 이 메일이 **간주 승인 7일의 근거**다(고객이 기한을 알 수 있었는지가 효력을 가른다). 메일은 기록마다 한 통.
5. **수정 요청·승인** — 고객은 진행 페이지에서 수정 요청·승인을 남긴다. 고객이 카톡으로만 말했다면 운영자가 "수정 요청 (의뢰인 대신 기록)"·"승인 (의뢰인 대신 기록)"으로 대신 남긴다.
6. **7일 간주 승인** — 전달일과 통지가 실제로 나간 날 중 **늦은 날**부터 7일. 기한이 지나면 매일 도는 기한 점검 크론이 승인을 기록한다. 기한이 지난 뒤의 수정 요청은 거절된다. 통지가 실패했다가 다시 나가면 그날부터 7일.
7. **최종 파일 인도 → 완료 처리** — 마스터링 승인과 잔금(또는 일시불) 입금이 끝나면 "최종 파일 인도". 개인정보 3년 보관은 최종 인도일부터 센다.
- **진행 페이지**: 계약 상세의 "진행 페이지 링크 복사"로 고객용 진행 화면(`/contracts/production/{id}/progress`) 링크를 카톡에 보낼 수 있다. 진행 단계는 관리자 상세에서 한눈에 본다.

## 6. 링크 관리

| 할 일 | 관리자 화면 | 명령 |
|---|---|---|
| 보낸 링크 현황 | 계약 목록 | `contract-link.ts list` — 최근 20건, **상태(만료 포함)·발송·만료 시각·열람 횟수(처음 연 시각)**, 서명 대기 링크 |
| 만료·재전송 | 상세 "재발송" | `contract-link.ts resend <계약 id>` — **옛 링크는 즉시 무효**, 새 링크 출력 → 카톡으로 다시 보낸다. 서명 대기·만료 상태만 가능 |
| 취소 | 상세 "계약 취소" | `contract-link.ts cancel <계약 id>` — 링크가 "취소된 계약"으로 열린다. **체결된 계약은 취소가 아니라 해지**(관리자 화면) |

- 서명 링크는 **발송 후 7일**에 만료된다(`SIGN_TOKEN_TTL_DAYS`). 만료는 별도 배치 없이 접근 시점에 판정한다.
- 링크 계약은 **고객 메일이 없어 자동 독촉이 없다.** "안 열어 봄"이 길면 카톡으로 직접 챙긴다(`list`의 열람 표시가 단서).
- **헬스체크 알림**(`checkProductionContracts`, [healthCheck.ts](../../../lib/ops/healthCheck.ts)):
  - 서명은 끝났는데 후처리(서명본 PDF·체결 메일) 기록이 없음 — high
  - 메일·PDF 처리 실패 기록이 있는 계약 — medium (상세 맨 위 오류 안내 확인 후 "완료 메일 재발송")
  - **이틀 안에 만료되는 서명 대기 링크** — 카톡으로 한 번 더 안내하거나 만료 후 재발송
  - **서명 없이 만료된 링크(최근 3일)** — 진행할 계약이면 재발송

## 7. 매출에 어떻게 잡히나

- 계약 대금은 결제 행(`payments`)을 남기지 않는다. 운영자가 남긴 **"입금 확인" 기록 하나가 매출 한 행**이다(일시불 1행, 계약금·잔금이면 2행). 그래서 **입금 확인을 안 남기면 매출 현황에서도 빠진다.**
- 관리자 매출 현황에서 믹싱·마스터링 계약은 **"믹싱·마스터링"**, 싱글·EP·정규 제작 계약은 **"음원 제작"** 유형으로 나온다.
- 기준 시각은 입금 기록 시각, 무효 처리한 기록은 제외. 금액은 부가세 포함이고 부가세는 역산한다. 해지 후 환불은 **환불 송금을 마쳤을 때**(`refund_accounts.refunded_at`) 늦은 입금 행부터 차감된다.
- 이름·연락처는 매출 행에 싣지 않는다. (출처: [productionRevenue.ts](../../../lib/ops/productionRevenue.ts))

## 8. 자주 하는 실수 / 주의

- **발송한 계약은 고칠 수 없다.** 금액·트랙 수·납품 기한이 틀렸으면 `cancel` 후 새로 만든다(옛 링크는 취소돼 열리지 않는다). 발송 전 미리보기에서 한 번 더 확인.
- **미성년자**는 링크 계약 불가(서명 화면이 막는다). 법정대리인을 넣는 일반 계약으로.
- **이메일 오타** — 서명본 PDF가 고객이 적은 주소로 가므로 오타면 남에게 갈 수 있다. 서명 화면이 확인 칸으로 막지만, 체결 후 고객이 메일을 못 받았다면 상세의 "완료 메일 재발송"(주소 확인 뒤)과 카톡 안내.
- **링크를 1:1 방 밖에 올리지 않는다.** 본인 확인 대신 이 전제로 성립한다.
- **입금 확인 누락** → 고객 독촉 메일 + 매출 누락. 입금 날 바로 기록.
- 서명 대기 중 계약이 있을 때 계약서 템플릿 파일을 고치지 않는다(읽은 조항과 서명 조항이 갈릴 수 있다). 새 계약은 작성 시점 템플릿 사본으로 완성된다.
- 마이그레이션 0078(믹싱·마스터링 종류 허용)이 운영 DB에 적용돼 있어야 믹싱·마스터링 계약이 저장된다. 저장 단계에서 CHECK 오류가 나면 이것부터 확인. 결제 링크 연동은 0079(계약↔결제 링크 표)가 필요하다 — 없으면 결제 링크가 생기지 않을 뿐 계약은 그대로 돈다.

## 9. 결제 페이지 연동

- 의뢰인이 서명하면 대금(일시불이면 전액, 분할이면 계약금) **결제 링크가 자동으로 생긴다.** 서명 완료 화면·체결 메일·진행 페이지에 "결제하기" 버튼이 붙고, 카드·간편결제·계좌 입금 중에서 고른다. 출처: `lib/contracts/production/payment-link.ts`, `lib/contracts/production/finalize.ts`.
- **카드·간편결제로 결제되면 진행 기록에 입금이 자동으로 남는다**(수행자 `system:payment`). 운영자가 "입금 확인"을 누를 필요가 없고, 그 결제 링크는 바로 닫힌다. 출처: `lib/booking/confirmDeposit.ts`.
- **결제 페이지에서 계좌 입금을 고른 경우**에는 관리자 예약 화면에서 그 주문의 "입금 확인"을 누르면 계약에도 함께 기록된다(두 번 적지 않는다). 출처: `lib/booking/bankDeposit.ts`.
- **결제 페이지를 거치지 않고 계좌로 직접 받은 돈**은 지금처럼 계약 상세에서 "입금 확인"을 남긴다. 그러면 열려 있던 결제 링크가 남은 금액에 맞게 바뀌거나 닫힌다(이미 받은 돈을 또 받지 않게).
- 분할 계약은 마스터링이 승인되면 잔금 링크가 생긴다(추가 비용·초과 수정 요금 포함). 잔금 기한 안내 메일의 버튼이 그 링크다.
- 계약을 취소·해지·완료하면 열린 결제 링크는 닫힌다. 관리자 계약 상세 "결제 링크" 칸에서 상태(열림·결제됨·닫힘)를 보고 링크를 복사할 수 있다.
- 매출: 결제 링크로 받은 돈은 결제 기록으로 매출 현황·주문 CSV에 잡힌다(계약 입금 집계에서는 빼서 두 번 세지 않는다).
- 해지할 때 카드 결제분 환불은 관리자 결제 링크(예약) 화면에서 직접 한다(자동 취소는 아직 없다).
