# Repository Guidelines

## Project Structure & Module Organization
This is a Next.js Pages Router app. Route files live in `pages/`, shared UI in `components/`, server and SEO helpers in `lib/`, shared data in `data/`, and browser/client utilities in `utils/`. Markdown story sources live in `content/stories/`; generated manifests such as `lib/story-catalog.json` and `lib/portfolio-meta.json` are produced by scripts. Static assets and generated sitemap/robots files live in `public/`. Automation and audit scripts live in `scripts/`; retired one-off codemods live in `scripts/archive/` and must never be executed (see `scripts/archive/README.md` — they encode stale facts and overwrite content in place).

## Build, Test, and Development Commands
Use `npm run dev` for local development. `npm run generate:manifests` refreshes portfolio and story manifests. `npm run type-check` runs TypeScript, `npm run lint` runs ESLint, and `npm test -- --watchAll=false` runs the Jest suite in CI mode. `npm run build` runs image/font optimization, manifest generation, Next.js build, sitemap generation, and sitemap hreflang normalization. Vercel cron configuration lives in `vercel.json`.

## Coding Style & Naming Conventions
Follow the repo's existing TypeScript/React style with 2-space indentation in TSX-heavy files and current local formatting in touched files. Name React components in `PascalCase`, helpers and hooks in `camelCase`, and public URLs in kebab-case. Favor existing Tailwind utility patterns and shared components over one-off styling. Keep generated artifacts current when changing content, sitemap inputs, story metadata, or portfolio metadata.

## Testing Guidelines
Jest with Testing Library covers UI, routing, middleware, SEO, API, and content integrity checks. Co-locate focused tests near the behavior when practical, or use existing root-level integration tests for cross-cutting route/build invariants. For changes touching story routes, manifests, sitemap behavior, contact delivery, or cron reports, run the specific test first and then `npm test -- --watchAll=false`. Run `npm run build` before shipping changes that affect generated content, SSG props, sitemap output, or Vercel runtime behavior.

## Operations Notes
GSC/GA4 diagnosis starts from `docs/gsc-raw/`, `docs/ga4-raw/`, `scripts/gsc-pseo-audit.mjs`, `lib/seo/gscAudit.ts`, `lib/seo/gscDiff.ts`, and `pages/api/cron/gsc-audit.ts`. The weekly GSC cron stores snapshots in Vercel Blob and emails a report on each scheduled run unless `?dry=1` is used. Contact and OG rate limits use Redis REST-compatible `KV_REST_API_URL` / `KV_REST_API_TOKEN` env names for deployment compatibility, without depending on a provider SDK.

## Commit & Pull Request Guidelines
Write succinct, sentence-style commit subjects, optionally with a scope. PRs should state user-visible impact, mention generated artifacts, include screenshots or measurements for UI/performance changes, and call out skipped checks. Keep dirty-tree discipline: preserve unrelated local changes and stage only files relevant to the requested work.

**Commit body is mandatory for any commit touching 10+ files or generated by a batch script.** The body must state (1) what changed and why, (2) the rule/policy behind a sweeping change (e.g. the regex or script used), and (3) how it was verified. One-line messages on mass changes destroy traceability — a 714-file commit with a one-line subject cost a full forensic pass in the 2026-07 audit. This applies to every agent (Claude, Codex, or otherwise) working in this repo.

## Canonical Facts (all agents must follow)
Studio facts (services offered, phone number, station exits, pricing) have a single source of truth: `docs/wiki/entities/services.md` and `docs/wiki/entities/naver-place.md`. `lib/factGuards.ts` enforces the critical subset in CI (`content/factGuards.test.ts`). Before writing content that states a fact about the studio, check the wiki. Never claim: vocal/instrument lessons (only producing lessons exist), English-speaking engineers (English = booking + remote mixing only), the retired 0507 number, or wrong station exits (Yeonsinnae exit 4, Bulgwang exit 7). If a fact changes, update the wiki and `lib/factGuards.ts` together.
